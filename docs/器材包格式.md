# 器材包格式

器材包是一个 **JSON 文件**，用来往小墨实验室里添加新器材。

它之所以安全，是因为包里的内容**全是数据**：没有脚本、没有 `eval`、
没有 `import`、不需要解压。每件器材都必须声明自己派生自哪件已有器材
（`proto`），渲染、电路特性、物理化学耦合这些行为**全部继承原型**，
你只能覆盖名称、外观尺寸、端口、默认参数和可调字段。

换句话说：**器材包改不了程序，只能配置程序。**

---

## 最小示例

```json
{
  "format": "xiaomo.equipment.pack",
  "version": 1,
  "id": "demo.pack",
  "name": "演示器材包",
  "author": "你的名字",
  "desc": "一句话说明这个包是干什么的",
  "equipment": [
    {
      "type": "demo-big-battery",
      "proto": "battery",
      "name": "大号干电池",
      "desc": "电动势更高的干电池，内阻也更大",
      "icon": "🔋",
      "defaults": { "emf": 9, "internalR": 1.2 }
    }
  ]
}
```

保存成 `任意名字.xiaomo-pack`（或 `.json`），然后从
**📦 器材包 → 导入器材包…** 装进去，左侧器材面板立刻就能看到它。

---

## 顶层字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `format` | ✅ | 固定为 `"xiaomo.equipment.pack"`，写错会被拒绝 |
| `version` | | 目前是 `1` |
| `id` | ✅ | 包的唯一标识，建议用 `作者.包名` |
| `name` | | 显示在器材包列表里的名字 |
| `author` | | 作者 |
| `desc` | | 一句话说明 |
| `equipment` | ✅ | 器材数组，至少一件 |

## 器材字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `type` | ✅ | 器材唯一标识，不能和已有器材重名 |
| `proto` | ✅ | 派生自哪件已有器材，必须是已注册的类型 |
| `name` | | 面板上显示的名字，不填就用原型的 |
| `desc` | | 面板上的说明文字 |
| `icon` | | 一个 emoji 或字符 |
| `domain` | | `physics` / `chemistry` / `bridge`，不填继承原型 |
| `cat` | | 面板里的分组标题，如「电源」「玻璃器皿」 |
| `tags` | | 字符串数组，用于搜索 |
| `w` / `h` | | 画布上的宽高（像素） |
| `ports` | | 接线柱数组，见下 |
| `defaults` | | **最常用**：覆盖可调参数的初始值 |
| `state` | | 覆盖初始运行状态 |

### ports（接线柱）

不填就继承原型的接线柱。填了会整体替换：

```json
"ports": [
  { "id": "pos", "x": 0.9, "y": 0.5, "polarity": "+" },
  { "id": "neg", "x": 0.1, "y": 0.5, "polarity": "-" }
]
```

`x` / `y` 是相对器材左上角的**归一化坐标**（0~1）。

## 怎么知道有哪些原型可以用

打开浏览器控制台：

```js
window.xiaomo.host.registry('equipment').list().map(d => d.type)
```

会列出全部可用类型。常用的有：

| type | 说明 | 主要参数 |
| --- | --- | --- |
| `battery` | 干电池 | `emf`（电动势 V）、`internalR`（内阻 Ω） |
| `switch` | 开关 | `closed`（是否闭合） |
| `lamp` | 小灯泡 | `ratedV`、`ratedP` |
| `resistor` | 定值电阻 | `resistance`（Ω） |
| `rheostat` | 滑动变阻器 | `rMax`、`pos`（0~1） |
| `ammeter` | 电流表 | `fullScale` |
| `voltmeter` | 电压表 | `fullScale` |
| `thermistor` | 热敏电阻 | `r25`、`B` |
| `heater` | 电热丝 | `resistance`、`maxP` |
| `motor` | 电动机 | `resistance` |
| `beaker` | 烧杯 | `capacity`（mL） |
| `testtube` | 试管 | `capacity` |
| `flask` | 锥形瓶 | `capacity` |
| `cylinder` | 量筒 | `capacity` |
| `alcoholLamp` | 酒精灯 | `power` |
| `electrode` | 电极 | `metal` |
| `thermometer` | 温度计 | — |
| `phMeter` | pH 计 | — |
| `glassRod` | 玻璃棒 | — |
| `balance` | 天平 | — |

> 具体参数名以运行时的实际定义为准，上面列的是常用项。
> 覆盖一个不存在的参数不会报错，只是没有效果。

## 派生是「继承 + 覆盖」

派生出来的器材和原型**完全等价**，只是换了几项配置：

- 原型能导电 → 派生品也能导电，一样进电路求解
- 原型是容器 → 派生品也是容器，`capacity` 改掉即可
- 原型参与电解 → 派生品照样产氢产氧
- 原型能被烧坏 → 派生品照样受损坏规则约束

所以「500 mL 的宽口烧杯」不需要写一行代码：

```json
{
  "type": "wide-beaker",
  "proto": "beaker",
  "name": "宽口烧杯",
  "w": 92,
  "h": 84,
  "defaults": { "capacity": 500 }
}
```

## 会被拒绝的情况

导入时会逐条检查，**任何一条不过就整包拒绝**（不会装到一半留下半套器材）：

| 情况 | 提示 |
| --- | --- |
| 不是 JSON 对象 | 不是一个 JSON 对象 |
| `format` 写错 | 不是小墨器材包（format 应为 …） |
| 没有 `id` | 缺少包标识 id |
| `equipment` 为空 | 包里没有任何器材 |
| 器材缺 `type` | 第 N 件器材缺少 type |
| 包内 `type` 重复 | 器材标识「…」在包里重复出现 |
| 器材缺 `proto` | 器材「…」缺少 proto |
| `proto` 指向不存在的类型 | 器材「…」引用了不存在的原型「…」 |
| `type` 和已有器材重名 | 器材标识「…」已被占用 |

同一个 `id` 的包重复导入时，会**先卸掉旧版本再装新的**，
所以修改器材包之后直接重新导入即可，不用先手动卸载。

## 卸载

在 **📦 器材包** 里点对应包的「卸载」，包里的器材会从面板消失。
已安装的包记录在 `localStorage['xiaomo.packs.v1']`，重开软件会自动装回来。

> 如果场景里已经摆了某件器材、而它的包被卸载了，那件器材会读不出来。
> 卸载前先清空实验台比较稳妥。
